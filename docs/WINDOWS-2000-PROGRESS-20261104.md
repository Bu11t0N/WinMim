# Windows 2000: implementation checkpoint

This is an intermediate implementation, **not acceptance of the full Windows 2000 mode**. Work was shortened at the user's request. Integration belongs to the coordinator; this branch has not been merged into main.

## Implemented

- A separate `windows2000` module profile keeps the `windows-2000` appearance ID and legacy journal paths. Open-Shell owns Explorer commands; RetroBar remains the taskbar owner. The navigation-bar removal module is excluded. AeroExplorer handles ribbon removal and address geometry.
- Open-Shell Explorer configuration: compact toolbar, Back/Forward/Up, Folders, Cut/Copy/Paste/Delete, views, folder options and actual selected-object properties. The existing text-address adapter replaces the Quero dependency. The archive's incorrect enabled Cut icon is not used as its disabled image; missing disabled images are generated by Open-Shell.
- An appended `ExplorerToolbarRequest` operation handles the source-confirmed `ShowedToolbar` DWORD 0 → 1 acknowledgement. The original value and existence are kept exactly. Only this operation accepts the acknowledgement; arbitrary other values/types remain conflicts. Old journal enum values are unchanged.
- A private, versioned resource manifest and importer cover 31 ICOs, six WAV files mapped to seven events, and four CURs. Each entry records role, size, SHA-256 and source. Desktop/menu/folder/drive resources use an `Assets2000` namespace. Missing required resources and the pinned Classic Explorer DLL are checked before dismantling an active appearance.
- The private images are candidates attributed by their collection to Windows 2000. They have not been certified against original installation media. The archive labels the cursor folder as Win98. Neither fact is hidden or treated as a redistribution license.
- A per-process, event-driven client-edge option is enabled only for 2000. It targets Notepad Edit, Console and the named Notebook control, records only its own missing edge bit, tags window lifetimes, removes hooks and restores that bit without replacing other style bits. No archived AHK executable, polling loop or Winlogon recipe is used. Runtime coverage of the option remains incomplete.
- The Start menu caption is Windows 2000 Professional. Its Help item opens an installed local WinMim help text, instead of relying on unavailable original Windows Help. No people/printer-search or undock decoration was added.
- Clean-baseline recovery no longer tries to restart a nonexistent previous managed host.

Final source also suppresses Open-Shell's first-run style dialog/new-program highlighting, disables the extra native status bar and hides Quick Access. These last corrections need a new deployed GUI pass. The menu caption font, remaining native navigation buttons and full Explorer layout still need refinement.

## Evidence and limits

Tested host: Windows 10 IoT Enterprise LTSC 2021 x64, build 19044, RU, 100% DPI, in an isolated clone. No Windows 11 compatibility claim.

- Final source: 62 Core tests and 12 Python tests passed. The importer tests cover changed hashes, out-of-bounds ICO entries and source traversal, with no output created on failure. Native verification passed for 56 DLLs: hashes, architecture and `Wh_ModInit` exports.
- An actual application completed in about 32.8 seconds; the runner checked the native palette/metrics and exactly one RetroBar.
- Real guest mouse clicks, rather than only UIA Invoke acknowledgements, confirmed Up, Copy/Paste, Cut/Paste to a second folder, Delete and selected-file properties. Filesystem checks confirmed the copy, move and deletion. The recycle-bin image changed after deletion. Some toolbar UIA Invoke calls produced no operation, so those calls were not counted as functional evidence.
- An actual Start click first exposed the Open-Shell first-run settings dialog. After cancelling it, another click opened the classic menu. The new first-run setting has not yet been rechecked on a clean deployment.
- Actual screenshots show Start, Explorer, file properties and WinMim responding to the classic session. They also expose duplicate status bars/modern navigation in that deployed revision. Screenshots are private handoff evidence, not substituted renderings.
- An initial test runner failed because asynchronous progress callbacks concurrently appended to one log. Its transaction was recovered. The runner now reports progress synchronously and does not let an IO failure in progress logging terminate a transaction. This failure is not counted as successful acceptance.
- The first recovery exposed the missing-baseline-host defect described above. Reapplication succeeded after the fix. Final baseline recovery status is recorded in the private handoff, not inferred from a process launch.

The complete repeat/95/2000/baseline matrix, transitions with the separately developed XP build/Seven, error/cancellation matrix, logoff/logon, cold start, 125% DPI, x86 application GUI checks, control-edge runtime restoration, tray/volume/language/overflow and idle CPU/RAM remain outstanding. So do the original-2000 visual comparison, full system/display/taskbar dialogs and login fidelity.
