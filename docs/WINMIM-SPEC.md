# Техническое задание WinMim — Windows Mimicry

Дата: 23 октября 2026. Статус: согласовано пользователем; разрешение на реализацию получено 23 октября 2026.

## 1. Цель и эталоны

Создать открытый аналог Revert8Plus: собственная программа воспроизводит функции r8p и управляет необходимыми сторонними компонентами. Поведение сверять с предоставленным пользователем r8p.exe build 1137; внешний вид — с оригинальной Windows 7 и предоставленными снимками.

Первая версия: Windows 10 IoT Enterprise LTSC 2021 x64, оформление Windows 7. Основной стенд — имеющаяся ВМ 19044.1288. Совместимость с другими обновлениями проверяется отдельно. Полный набор функций достигается постепенно; Windows 11 и другие режимы оформления относятся к последующим версиям.

## 2. Что разрабатываем сами

- Мастер установки, интерфейс настройки, применение профиля, восстановление и удаление.
- Выбор, загрузка, проверка и настройка зависимостей; управление их запуском и порядком применения.
- Согласование состояния темы между сеансами и процессами, обновление оформления после входа и перезапуска оболочки.
- Необходимые специфичные для r8p адаптеры и перехваты, если готовые компоненты не обеспечивают требуемое поведение.
- Журнал изменений, диагностику ошибок и повтор прерванных действий.

Принципы и наблюдаемое поведение оригинала служат основанием для собственной реализации; код автора r8p не переносится. Код Windhawk и других выбранных сторонних проектов не требуется переписывать. Для каждой функции фиксируются используемый компонент либо наша реализация и результат проверки.

Из AeroForge сохраняются только подходящие части. Название, прежняя архитектура и собственные мини-приложения AeroForge не должны мешать соответствию r8p. Это не обязательный переписанный с нуля проект.

## 3. Пользовательский сценарий

Интерфейс по структуре похож на r8p: приветствие, проверка совместимости, выбор состава, понятный прогресс, завершение. Внешний вид интерфейса реализуется собственными средствами.

Основное действие — «Применить оформление Windows 7». После установки доступны просмотр состояния компонентов, повторное применение, изменение состава и удаление. Пользователь видит конкретную ошибку и способ продолжить, а не только сообщение об общем неуспехе.

Права администратора и перезагрузка допустимы. Перезапуск Explorer и Windows объясняется перед выполнением; автоматическая перезагрузка без предупреждения не выполняется.

## 4. Первый законченный результат

Одна установка и одно применение дают совместно работающие:

- тему окон и контролов, рамки, кнопки заголовка, прозрачность DWM и согласованные цвета;
- меню «Пуск», кнопку Start, панель задач и базовое оформление трея;
- Проводник с классической командной панелью, панелью сведений и согласованным оформлением;
- сохранение выбранного оформления после входа и перезагрузки;
- восстановление исходного состояния управляемых настроек при удалении.

Сторонний компонент допускается, если обеспечивает требуемый результат. Например, Open-Shell не считается окончательным решением автоматически: его вид и поведение необходимо сопоставить с эталоном.

## 5. Последующие этапы полного аналога

1. Остальная оболочка: значки и ресурсы, контекстные меню, системные всплывающие окна, часы, копирование файлов, Alt+Tab, Aero Peek и прочие эффекты набора Windows 7 в r8p.
2. Дополнительные приложения: игры, гаджеты, медиакомпоненты и справка — по функциям оригинала, с явным выбором состава.
3. Системные области: UAC, экран входа и остальные затрагиваемые оригиналом системные диалоги. Проверять в отдельном восстанавливаемом стенде.
4. Единый установочный пакет, обновление WinMim и компонентов, офлайн-установка.

До объявления полного соответствия составляется конечный список функций build 1137 со статусами «готово», «не готово», «не относится к выбранной ОС/режиму». Число загруженных DLL не заменяет этот список и проверки поведения.

## 6. Установка и восстановление

Предлагаемое решение для согласования: сначала установка с интернетом и локальным кешем, затем переносимый офлайн-пакет. Уже установленное оформление не должно требовать постоянного подключения.

Загрузки имеют таймауты, ограниченные повторы и проверку файлов. Сбой загрузки не должен разрушать уже рабочую установку; пригодный кеш сохраняется для продолжения.

Перед изменениями сохраняются исходные файлы, типы и значения настроек. Повторное применение не заменяет исходную резервную копию. Возвращаются конкретные управляемые значения; целые чужие ветви реестра не удаляются. Поздние изменения пользователя сохраняются как конфликты и показываются в отчёте.

Требование точного возврата распространяется на компоненты, которые установил или изменил WinMim. Для внешних установщиков заранее определить способ удаления и пределы восстановления. Снимок ВМ — дополнительная страховка при разработке, а не замена функции удаления продукта.

## 7. Приёмка и порядок работы

Первый этап принимается после видимого сравнения с Windows 7, проверки основных действий «Пуска»/панели задач/Проводника, повторного применения, перезапуска Explorer, выхода и входа, перезагрузки и удаления. Отдельно проверить прерванную загрузку и неудачное применение. Результат — рабочая сборка в ВМ, короткий отчёт и снимки, а не только автоматические тесты.

Разработку вести небольшими законченными шагами. Проверять конкретное изменение; не продолжать общий сбор системы и повторные одинаковые проверки без практической необходимости. Оставшиеся неисправности отмечать прямо.

Пока проект личный: внешние темы, ресурсы и закрытые компоненты допустимы. Собственный код предполагается открытым, с сохранением GPL-3.0 текущего проекта; лицензии сторонних компонентов учитываются отдельно. Публичный выпуск и состав распространяемых ресурсов сейчас не входят в этап.

После согласования этого ТЗ требуется отдельное явное разрешение пользователя начать реализацию. До него код, ВМ и настройки программы не изменять.
