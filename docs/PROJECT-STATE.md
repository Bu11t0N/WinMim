# WinMim: договорённости, состояние и продолжение

Актуально на 30 октября 2026, Europe/Moscow. Сводка для продолжения разработки без повторного исследования чата. Программная контрольная точка — `808bcd7`, галерея — `4db063a`. Поздние изменения в этом документе имеют приоритет над историческими отчётами с меньшей датой. Секреты и подробности доступа к стенду здесь не хранятся.

## Что хочет пользователь

Уточнение от 30.10: публичный README должен описывать возможности и проверенную версию ОС, без имени нашей ВМ и оперативной истории стенда. Следующее расширение — [классические оформления до XP](CLASSIC-PRE-XP-PLAN.md); XP пока не разрабатывать и не добавлять как рабочее оформление. Это уточняет прежний долгосрочный список, не удаляя существующую заглушку XP.

WinMim — Windows Mimicry: открытая программа, которая воспроизводит внешний вид **и поведение** выбранного поколения Windows. Цель — максимально близкое сходство и при обычной работе, и при переходах в свойства, Проводник, системные меню и диалоги. Одних обоев, цвета и приблизительных значков недостаточно.

Изначальный ориентир функций — предоставленный пользователем Revert8Plus build 1137, ориентир оформления — настоящая Windows 7, её ВМ и снимки. Наша обвязка, планирование, установка, диагностика и восстановление пишутся самостоятельно. Windhawk, Open-Shell и другие сторонние проекты можно использовать как зависимости; переписывать весь их код не требуется. Из старого AeroForge сохраняем только полезные решения. Внутренние имена AeroForge пока нужны для совместимости журналов и путей.

Первая рабочая платформа — Windows 10 IoT Enterprise LTSC 2021 x64, семейство сборок 19044. Состав функций r8p достигается постепенно, но промежуточную сборку нельзя объявлять полным аналогом. В перспективе: хосты Windows 10/11 и оформления 95, 98, Me, 2000, XP, Vista, 7, 8, 8.1, 10, 11. Этот список не означает, что все варианты уже реализованы.

Пользователь отдельно попросил реализовать Windows 95. Остальные неготовые варианты остаются заглушками до реализации. Выбор строки каталога сам по себе не должен менять ОС. Рабочая интеграция Seven пока находится на отдельной вкладке «Windows 7 (стенд)».

Интерфейс утилиты использует системные контролы, шрифты, цвета и рамки: он тоже должен реагировать на глобальное оформление. Собственная брендовая тема интерфейса убрана. Структура мастера может напоминать r8p. Иконка WinMim предоставлена пользователем и уже встроена в приложение.

Допустимы права администратора, внешние зависимости и необходимые перезапуски. Для личного стенда допустимы отдельные несвободные ресурсы; это не означает разрешение включить их в публичный GPL-архив. Репозиторий сначала был закрытым, затем по прямому запросу пользователя стал публичным: [Bu11t0N/WinMim](https://github.com/Bu11t0N/WinMim).

## Как работаем

- Экономить кредиты: одна конкретная проблема, измеримое исправление, подходящая проверка, результат. Не повторять уже прошедшие полные проверки без новой причины.
- При низком бюджете приоритет — баги, точность уже работающих оформлений и оптимизация. Не начинать одновременно несколько новых оболочек.
- Не просить повторное разрешение на уже согласованную разработку и обратимые действия в стенде. Новые сведения пользователя уточняют текущую задачу.
- Оформление проверять в ВМ, основной компьютер пользователя не переоформлять. Снимки настоящей Windows 7 и reference r8p сохранять как эталоны.
- Разовая старая просьба выключить компьютер уже была выполнена; она не является постоянным разрешением выключать его после каждой задачи.
- Показать реальное окно, меню или переход важнее, чем снова подтвердить только `Loaded`. Автоматический тест не доказывает визуального совпадения.

### Последние исправления и оптимизация

1. Асинхронное возобновление оболочки больше не блокирует диспетчер приложения синхронным ожиданием.
2. Нативные изменения Classic95 выполняются вне UI-потока; настоящий цикл кнопок Apply/Restore сохранял отзывчивость окна.
3. Отображаемая DLL при возврате может быть перемещена в собственный каталог Retired. Удаление освобождённых копий проверяет имя и хеш; изменённые чужие файлы сохраняются.
4. Важные системные, восстановительные процессы и VMware Tools исключены из неподходящих внедрений.
5. Собственный `winmim-classic-frames` меняет флаги оформления процесса и NC-отрисовку стандартных окон, восстанавливает свои изменения, работает по событиям без опроса. Профиль ограничен лабораторным компьютером.
6. В Classic95 отключены современные превью панели, выбран режим списка по нажатию. Для Seven это изменение автоматически не включалось.
7. История читает метаданные и ошибки без декодирования резервных DLL. На синтетическом наборе 6 журналов временные выделения снизились примерно с 24 до 4 МиБ. Это показатель конкретной операции, не общее потребление памяти приложения.
8. Упаковка исключает устаревшие сгенерированные модули, PDB, сырые диагностические данные и личные ресурсы.

Контрольная точка: **56 Core-тестов, 9 Python-тестов, 56 проверенных нативных DLL**. Настоящий UI-цикл Classic95 вернул палитру/метрики, флаги визуальных стилей и состояние рамки. За время применения прошло 54 тика UI-таймера. Контролируемое возобновление/возврат после перезагрузки проверено, обычный запуск Classic95 всё ещё нуждается в привилегированной фазе. Полностью автоматический запуск после входа не заявляется.

## Что произошло с чёрным экраном и смешанным оформлением

Проблемные состояния сохранены отдельно; основной стенд восстанавливался на известный Seven-снимок. Были найдены зависания управляющего UI и проблемы возврата загруженных DLL, затем проверены исправления. Это не доказывает, что установлена единственная причина первоначального чёрного экрана.

Поздняя смешанная картинка 95 включала современную рамку/превью и классическую палитру. После отдельного исправления процесса отрисовки на снимке уже видны настоящие классические рамки и контролы. Современный трей, часть Explorer и программы с собственной отрисовкой всё ещё отличаются.

Один из снимков чистой ВМ готовился долго из-за медленного дискового ввода-вывода. Позже VMware Tools и приложение запустились штатно. Медленная загрузка сама по себе не является новым доказанным багом WinMim.

## Текущая задача Windows 7

Пользователь видит странную фактуру панели и неправильный цвет «Пуска». Это открытый дефект. В `DesktopProfile.BuildSeven` до сих пор используются наша PNG 16×40, стандартный скин `Windows Aero`, отдельные фиксированные оттенки и прозрачности панели/меню. Связь этих настроек с наблюдаемой картинкой нужно проверить, а не объявлять причиной без A/B-сравнения.

Подробное исследование YouTube, специальных скинов и план эксперимента: [SEVEN-APPEARANCE-RESEARCH-20261030.md](SEVEN-APPEARANCE-RESEARCH-20261030.md).

### Ближайший порядок

1. На отдельной копии Seven сохранить текущую конфигурацию Open-Shell и контрольный снимок. Эталон Windows 7 снимать при одинаковых разрешении, DPI, обоях и фоне под меню.
2. Сравнить вариант без нашей текстуры, затем одну подходящую текстуру, затем специальный скин Windows 7. Менять по одному слою; не менять одновременно DWM-движок.
3. Согласовать фон, альфа-канал, оттенок, размытие, рамки и свечение меню/панели. Отдельно проверить 100%/125%, высоту панели и её положение.
4. Проверить кнопки обычная/активная/наведение, несколько сгруппированных окон, Aero Peek, «Показать рабочий стол», трей и контекстные меню. Нажатия должны открывать исторически подходящие назначения.
5. Результат включать в координатор только после реального снимка и возврата. Затем обновить галерею и отметить закрытые строки списка расхождений.

### Дальше по Seven

Полнота значков и курсоров; размеры и интервалы Проводника; детали трея/уведомлений/переключения языка; классические громкость, сеть и календарь; Alt+Tab; системные диалоги; согласованность контекстных меню; экран входа/UAC. Игры, WMC, гаджеты и DVD-зависимость требуют проверки реальных функций и корректного удаления. Не считать незавершённые проверки успешно пройденными.

### Дальше по платформе

RetroBar + Open-Shell — отдельный кандидат для ближайшего семейства классических тем до XP. XP и Vista сейчас в этот прототип не включать. Не путать его классическую панель с полноценной суперпанелью Windows 7. На каждой поверхности должен быть один управляющий компонент. Другой DWM-движок испытывать как альтернативу, а не накладывать поверх текущего.

Нужны контракты компонентов: обнаружение, сборки хоста, закреплённый пакет/исходник, права на ресурсы, настройки, применение, проверка состояния и возврат. Новая тема готова только при согласованном наборе ресурсов и поведения, а не после добавления строки каталога. Windows 11 требует собственного стенда и проверки, выводы Windows 10 на неё не переносятся автоматически.

## Как продолжить без потери времени

Сначала прочитать этот файл, последнее исследование Seven и точечный отчёт затронутого компонента. Проверить текущий Git и состояние нужной ВМ. Не воспроизводить заново весь многодневный перенос.

Локальный `NEXT-SESSION.md` хранит оперативные пути, команды стенда и свежие результаты; в Git не публикуется. Там нет необходимости повторно печатать секреты. Старые отчёты с меньшим числом тестов — исторические, а не признак потери новых функций.

При проблемах захвата VMware не заменять реальные проверки бесконечными проверками загрузки DLL. Штатные команды компонентов и VMware API подходят для подготовки/сохранения снимков. Если интерактивный переход не проверен, так и записать.
