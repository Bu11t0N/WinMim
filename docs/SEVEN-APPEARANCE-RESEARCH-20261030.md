# Windows 7: исследование оформления панели и «Пуска»

30 октября 2026. Запрос: найти дополнительные способы приблизить Windows 10 к Windows 7, особенно по YouTube, и разобраться с неудачной текстурой панели и оттенком меню. В этом проходе выполнены поиск, чтение доступных описаний и проверка исходников/документации. Видео целиком не просматривались; покадровая проверка не заявляется. Прямое открытие страниц YouTube через веб-инструмент завершалось ошибкой, но поисковая выдача предоставила описания двух роликов.

Версии в WinMim после исследования не обновлялись, новые компоненты не устанавливались. Скины и изображения требуют отдельного учёта происхождения; лицензия движка не распространяется автоматически на весь набор графики.

## Что установлено в нашем коде

Источник: [`DesktopProfile.cs`](../src/AeroForge.Core/DesktopProfile.cs), методы `BuildSeven` и `TaskbarTexture`.

| Параметр | Текущее значение |
| --- | --- |
| Текстура панели | Генерируемая PNG 16×40 RGBA; по ширине каждый ряд одноцветен, по высоте голубой градиент и светлая верхняя линия |
| Растяжение | `TaskbarTileH=Tile`, `TaskbarTileV=Stretch`, `TaskbarBordersV=1,0` |
| Панель | `CustomTaskbar=1`, `TaskbarLook=Glass`, `TaskbarOpacity=38`, `TaskbarColor=0x996F46` |
| Меню | `SkinW7=Windows Aero`, `GlassOverride=1`, `EnableGlass=1`, `GlassOpacity=25`, `GlassColor=0x93652F` |
| DWM | Ещё один отдельный набор параметров размытия, балансов и рамок |

В прочитанном исходнике Open-Shell `SkinManager.cpp::GetMenuGlassColor` берёт R из младшего байта, G из следующего, B из старшего. Поэтому наши COLORREF задают панели RGB `#466F99`, меню `#2F6593`. PNG содержит RGB уже в другом, обычном порядке каналов. Нельзя механически передавать RGB-число в поле COLORREF и считать цвета совпавшими.

`StartMenuDLL.cpp::ComputeTaskbarColors` и `MenuContainer.cpp::OnCreate` отдельно формируют цвет и альфа-канал композиции. Следовательно, общий оттенок визуального стиля не гарантирует одинаковое стекло панели и меню.

**Вывод из кода, требующий проверки в ВМ:** собственный рисунок, разные фиксированные оттенки, альфа-канал рисунка и отдельные прозрачности могут давать искусственный градиент и несогласованный цвет. Само наличие этих настроек подтверждено; конкретный вклад каждого слоя в жалобу пользователя пока не измерен. Повторение по горизонтали одноцветных рядов не создаёт само по себе горизонтального узора.

## Минимальный следующий эксперимент

1. Скопировать состояние Seven в отдельную ВМ; сохранить текущие значения Open-Shell, активный стиль и настройки DWM. Не пересоздавать весь стенд.
2. Подготовить сопоставимый эталон Windows 7: одинаковые разрешение, DPI, обои, масштаб/положение обоев и фон под открытым меню. Текущая публичная галерея — 1440×900, старый эталон пользователя — примерно 1024×768; напрямую подбирать оттенок по таким разным фонам нельзя.
3. Вариант A: нынешняя конфигурация. B: та же конфигурация без нашей PNG. C: одна проверенная текстура для нижней панели с подходящими границами. Проверять изменение после реального перезапуска нужного компонента.
4. При выбранной панели сравнить стандартный скин и один специальный Windows 7-скин. Начать с рекомендованных автором согласованных настроек, затем измерять отклонения. Не складывать старые фиксированные overrides с новым скином без проверки.
5. Проверить альфа-канал, предумножение при загрузке изображения, прозрачность и поведение размытия на светлом и тёмном фоне. Прозрачность меню, панели и текстуры — разные параметры.
6. Отдельно проверить 100%/125%, обычные/активные/наведённые кнопки, группы, свечение, края панели и «Показать рабочий стол». Скин красивого неподвижного меню не доказывает правильного поведения панели.
7. Зафиксировать один результат со снимками и журналом возврата. Только затем менять профиль по умолчанию и обновлять публичную галерею.

Готовность этого этапа: панель и меню имеют согласованные оттенок, размытие и блики в сопоставимых условиях; нет заметного искусственного рисунка; состояния кнопок проверены; пользовательские настройки сохраняются при возврате. Нулевое пиксельное отличие пока не обещается.

## Что сейчас намеренно отложено

Не переходить сразу на новый Explorer/DWM только ради оттенка панели. Не применять инструкции для Windows 11 к хосту Windows 10 без проверки. Не переносить неизвестные вложения из видеописаний и не запускать общие transformation packs. Платные StartIsBack/StartAllBack могут быть визуальным сравнением, но не должны становиться обязательной скрытой зависимостью открытой версии WinMim.
