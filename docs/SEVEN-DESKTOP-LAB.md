# Полное визуальное оформление Seven в лабораторной ВМ

22 октября 2026 года в `AEROFORGE-LAB` (Windows 10 LTSC 19044.1288) установлен составной профиль: Aero10 Seven, Open-Shell 4.4.198, SecureUxTheme 4.0.0, OpenGlass 3.0.2.3749 и пользовательский host AeroForge/Windhawk. Основная Windows компьютера не переоформлялась.

Результат: [настоящий рабочий стол ВМ](images/vm-seven-desktop.png), [обновлённое меню по эталону Windows 7](images/vm-seven-start-native.png). Показаны классическое меню «Пуск», кнопка Start, новая панель задач без поиска/Task View, тема стандартных контролов и рамок, обои, командная панель и нижняя панель сведений Проводника. Лабораторная интеграция доступна отдельной карточкой «Оформление Seven» в разделе «Компоненты»; верхняя кнопка «Запустить» по-прежнему запускает модульный host.

## Воспроизведение

1. Сохранить VMware snapshot. Для текущей ВМ исходная точка: `Before-full-desktop-2026-10-22`.
2. На компьютере с Интернетом получить пакеты: `python tools/fetch_desktop_packages.py --destination PATH --with-aero10`. Скрипт только скачивает и проверяет SHA-256. Передать полученные файлы в `C:\AeroForgeLab` гостя.
3. В госте запустить `tools/Install-SevenDesktopLab.ps1` с повышенными правами. Сценарий ограничен именем тестовой ВМ, не меняет основную Windows и не перезагружает гостя автоматически.
4. Перезагрузить гостевую Windows после установки SecureUxTheme.
5. Обычным интерактивным пользователем выполнить `tools/Set-SevenDesktop.ps1`. Не запускать этот сценарий с повышенным токеном. Сценарий вызывает CLI, а карточка интерфейса напрямую использует Core. Файлы, типизированные значения HKCU, активный visual style и обои входят в один журнал `%LOCALAPPDATA%\AeroForge\DesktopState`; собственные ресурсы находятся в `DesktopV2`. Тема применяется нативным API без открытия «Параметров».
6. Для обновления панели задач отметить перезапуск Проводника в карточке или передать `-RestartExplorer`. Открытые окна папок будут закрыты. Open-Shell: `StartMenu.exe -open` показывает меню, `-reloadsettings` перечитывает настройки.

## Работа без Интернета

ВМ не имеет сетевого адаптера. Установщики передаются с хоста. Windhawk использует кеш `Host\Data\Engine\Symbols` с каталогами `name.pdb/GUIDage/name.pdb`. Для текущего полного профиля дополнительно потребовались `windows.storage.pdb` (WOW64), `actioncenter.pdb`, `van.pdb`.

**OpenGlass использует другой формат:** файлы `dwmcore.pdb` и `uDWM.pdb` находятся непосредственно в `C:\ProgramData\OpenGlass\symbols`. Это подтверждено его `SymbolDownloader.cpp` и `SymbolParser.cpp`. Размещения только по структуре Windhawk недостаточно. Идентификаторы текущей ВМ: `94E805FD2E00CD8CE9E510E539EDF69F1` и `E101B0D7655ADFD5477ACBB138C9ED6C1`. Каждый файл проверяется по GUID, DBI age и SHA-256. PDB в дистрибутив не включены.

## Возврат и ограничения

`Set-SevenDesktop.ps1 -Action Restore` возвращает файлы, значения HKCU, активный visual style и обои, записанные перед применением. Повторное применение того же профиля возвращает прежний receipt и не заменяет исходную резервную копию. Изменённые после применения значения сохраняются как конфликты; CLI возвращает ненулевой код при неполном возврате. Живой цикл применения, повторного применения и возврата проверяется `AeroForge.VmSmoke --i-am-in-test-vm --desktop`; отчёт: `docs/evidence/desktop-native-19044.1288.json`. В уже оформленной ВМ точкой возврата служит состояние перед этим применением, а чистая Windows сохранена в snapshot. Старый журнал PowerShell `Desktop/settings.clixml` не смешивается с новым. Установка внешних компонентов не входит в его журнал: для полного возврата всей ВМ использовать исходный snapshot или штатные деинсталляторы компонентов.

Интеграция пока ограничена этой ВМ. Проверка DLL в DWM подтверждает загрузку OpenGlass, но не доказывает правильность каждого эффекта. Всплывающие окна, весь набор значков, экран входа, UWP, несколько мониторов/DPI и повторное накопительное обновление остаются отдельной матрицей испытаний. Полное соответствие Revert8Plus не заявляется.
