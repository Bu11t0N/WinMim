# Карта механизмов r8p build 1137 и AeroForge

Основание — статический разбор 54 файлов модулей из экземпляра пользователя. Динамическое подтверждение установки отмечается отдельно. Один файл не равен одной функции: варианты Seven/Vista/Basic/Classic часто повторяют один механизм.

| Группа оригинала | Механизм | Текущая опора AeroForge | Следующая проверка |
|---|---|---|---|
| `sys-themesvc-ex`, `sys-uxtheme-hook` | Передача/определение типа темы в процессах | Нативное применение visual style; внешний SecureUxTheme | Отдельный протокол состояния темы для каждого сеанса и процесса |
| `dwm-manager`, `theme-reloader` | Реакция DWM и Explorer на смену темы | Обновление настроек и управляемый перезапуск Explorer | Вход, смена профиля, повторный запуск модулей; текущая проблема пока открыта |
| Windhawk service | Работа до и после появления пользовательской оболочки | Portable host в пользовательском сеансе | Сравнить сервисный и пользовательский жизненный цикл; наличие службы само по себе не доказывает причину зависания |

## Что даст сравнение состояний

Оно покажет фактически созданные файлы/ссылки, изменения выбранных областей реестра, службы и задачи. Оно не объясняет код перехватов, формат ресурсов или то, какие подстановки происходят только внутри процесса. Поэтому сравнение используется вместе с изучением исходников и отдельными проверками поведения.

Приоритет после динамического замера: жизненный цикл движка и темы; перенаправления реестра/ресурсов; собственные графические ресурсы; затем системные режимы. Каждый новый эффект проходит через явный план изменений и проверку возврата. Наличие извлечённого исходника без установленной лицензии не служит разрешением на импорт в проект.

## Согласование состояния темы

В исходном sys-themesvc-ex тип Seven/Vista/Basic/Classic определяется по конкретным путям .msstyles и записывается по номеру сеанса в HKLM. Поэтому внешнего сходства темы недостаточно для совместимости модулей, которые ожидают этот протокол. Для AeroForge нужен собственный явный контракт состояния профиля с проверкой активной темы через API. Это вывод статического анализа, а не установленная причина наблюдавшегося зависания.
