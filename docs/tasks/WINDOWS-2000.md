## Конкретный перенос

### Проводник

Разбери `5. StartMenu/Explorer Settings.xml`: NoFadeButtons=1, TreeItemSpacing=-2, FullIndent=1, DisableBreadcrumbs=1, HideSearch=1, UseBigButtons=0, ToolbarListMode=1, ShowStatusBar=1. Реализуй согласованную строку меню, компактную панель Back/Forward/Up, Папки, Cut/Copy/Paste/Delete, виды, параметры папок, адресную строку/Go и статус. Иконки `Classic/win98buttons` и русские подписи — конкретный ресурсный ориентир, а не доказательство их соответствия 2000.

Проверь enabled/disabled/hover состояния. В исходном XML CutItem.IconDisabled совпадает с обычным ресурсом — не переносить эту неточность автоматически. `HKCU\Software\OpenShell\ClassicExplorer\ShowedToolbar=0` из видео исследуй как возможный способ включения toolbar, учитывая перезапись Open-Shell; журналировать исходное существование и значение.

Quero Toolbar installer x64 имеет версию 8.0.0.0. QueroWin2K.dll — отдельный ресурсный кандидат с ненулевым entry point и без COM-registration exports; не считать её безусловно безопасной DLL-данными и не регистрировать вместо toolbar. Проверь исходники/условия/совместимость. Выбери одну реализацию адресной строки: существующий адаптер, проверенный компонент либо собственная обвязка. Убери конфликты с aerexplorer, classic Explorer modules и Open-Shell toolbar. Видимые команды должны работать с файлами, навигацией, выделением и реальными свойствами.

### Панель, Start, рабочий стол и ресурсы

Сохрани современный закреплённый RetroBar, пока не доказана необходимость замены: архивный 1.9.46 старее уже используемого 1.22.122. Один владелец панели. Настрой геометрию, Quick Launch, группы/кнопки, часы, язык, tray/overflow, контекстные меню и классические свойства без случайных переходов в современные Settings.

Меню XML использует Classic1, ClassicC / Windows 2000 Professional, THICK_BORDER. `openshell.reg` расходится с XML: выясни фактически нужные значения, не импортируй всё. search_people/search_printer/help/undock требуют рабочих назначений или честного ограничения, без мёртвых декораций.

Отдельный набор ресурсов Windows 2000: Computer, документы, сеть, диски/папки, корзина empty/full, Start/toolbar, типовые диалоги; также курсоры, звуки, обои и типографика. Не оставлять общий набор 95 как завершённое решение. Подготовь manifests с ролями, SHA-256, размерами и происхождением. Оригинальные ресурсы для личного стенда держать отдельно от публичной поставки. Согласовать рамки, цвета, Tahoma, толщины, active/inactive/maximized и все основные контролы с оригинальной 2000.

### Классические контролы, диалоги и запуск

AHK bar/classic — версии v1, текст уже извлечён. Shell-hook, child-control edges `0x200` и перерисовка Notepad/Console/Notebook дают конкретные случаи для собственной узкой обратимой реализации. Не запускать два старых EXE поверх нашего наблюдателя. Исходные AHK не сохраняют стили для полного возврата; добавь учёт собственных изменений, очистку hooks и восстановление. Не вводить постоянный polling без необходимости.

Проверь Run, Open/Save, copy/progress, folder/system/display/taskbar properties, выключение и выход. LogOutClassicWindow 1.0.0.0 с ru-RU/cs-CZ — кандидат для анализа; действия должны действительно вызывать соответствующий системный механизм. Старые CPL не объявлять рабочими заменами: исследуй необходимые функции и адаптируй под хост.

Не переносить неизвестную модификацию StartMenuDLL.dll 4.4.1000 поверх нашего закреплённого Open-Shell (у архивного установщика версия 4.4.160). Не переносить Winlogon/Userinit → schtasks/Classic/ApplicationFrameHost, Defender-control, убийство чужих процессов по имени, branding DLL build 22000 на 19044 или весь старый EP REG. Цель — их визуальный/функциональный результат через управляемые изменения. `UserPreferencesMask` не перезаписывать целиком ради одного эффекта. Для Win10 необходимость ExplorerPatcher из Win11-рецепта не доказана.

## Архитектура и совместная работа

Работай в отдельном worktree/ветке `theme/windows-2000`; не редактируй рабочую копию XP-чата. Переиспользуй Classic95Setup, ClassicThemes, ClassicAppearance, RetroBarHost, ProfilePlanner, DesktopBackend, ресурсные адаптеры и журналы; специфичное для 2000 держи отдельно. Общие изменения минимальны и совместимы с XP/95/Seven. Сохрани существующий ID `windows-2000` и совместимость старых журналов.

Каждое изменение: проверка зависимости/хеша до записи, снимок исходного состояния, apply/resume/restore, сохранение чужих пользовательских правок, блокировка параллельных операций. Чужие процессы/настройки не присваивать. Автозапуск и восстановление делать через наш lifecycle. Недоступный обязательный пакет должен обнаруживаться до разрушения работающего оформления.

Испытания только в отдельном Windows 2000-profile clone со снимком; основной компьютер, общую ВМ, XP clone, оригинальные reference Windows и r8p не менять. Доступ к стенду уточнять по актуальным приватным continuation-файлам без вывода credentials. Права администратора и перезагрузка гостя разрешены; защищённый UAC не автоматизировать. Основной компьютер не выключать. Координатор выполняет итоговую интеграцию main.

## Приёмка и сдача

1. Законченный первый этап: согласованные desktop/Start/taskbar/Explorer, ресурсы 2000 и реальные команды. Затем завершай диалоги, login/resume и найденные расхождения; явно веди остаток до заявленной полной кастомизации.
2. Реальная ВМ: baseline → 2000 → повтор → 95 → 2000 → baseline; переходы XP/Seven проверять с доступной согласованной сборкой. Отмена/ошибка, Explorer restart, logoff/logon, холодный старт и возврат не должны терять desktop или оставлять двойную панель.
3. RU, x86/x64 приложения, 100/125% DPI; normal/maximized, active/inactive, enabled/disabled; реальные клики Start, Win/Ctrl+Esc, tray/volume, навигация/файловые команды. Loaded и открытие меню через CLI недостаточны.
4. Сравнить с оригинальной Windows 2000 при одинаковом DPI/разрешении. Если эталонной ВМ нет, получить проверяемые эталонные изображения и честно указать предел сравнения. Снимки: desktop+Start, Explorer, диалог, WinMim обычного размера. Никаких нарисованных вместо runtime кадров.
5. Подходящие regression-тесты общих изменённых путей; проверить build/content hashes, откат и сохранение пользовательских правок. Измерить idle CPU/RAM и время применения; не повторять полные проверки без новой причины.
6. Сдать ветку/commit, отчёт по каждому пункту, сопоставление видео → файл → наша реализация → доказательство, источники/лицензии, ограничения и инструкции восстановления. Отдельно перечислить, что из незавершённого исследования удалось закрыть. Private артефакты/старые бинарники/секреты не публиковать. Публичные инструкции — без имени ВМ и персональных путей из этого локального ТЗ.

Не заканчивай ещё одним планом. Начни с инвентаризации текущего профиля и первого видимого исправления Explorer/ресурсов, затем последовательно доводи режим до критериев. Препятствия конкретного компонента не должны останавливать независимые части работы.
