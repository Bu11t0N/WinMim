# Дальнейшая разработка

## Первый необходимый стенд

Стенд AEROFORGE-LAB с Windows 10 LTSC 19044.1288, Tools и снимками установлен. Seven/Vista прошли загрузку модулей и возврат; составное оформление Seven установлено, нативный журнал оформления проходит отдельный живой цикл. Пользователь предоставил эталонную Windows 7 и три снимка. Следующие стенды — Windows 10 с актуальным накопительным обновлением и поддерживаемая Windows 11. На основной машине внедрение модулей в Explorer/DWM в этой сессии не проверялось.

Для каждого сценария сохранять номер сборки и UBR, версии/хеши explorer.exe, ExplorerFrame.dll, dwmcore.dll, uDWM.dll, архитектуру, DPI, состав модулей и журнал событий при сбое.

## Порядок работ

1. **Прогнать Seven в VM.** Проверить каждый модуль отдельно, затем комбинацию. Вход/выход, перезапуск Explorer, смена DPI, несколько мониторов, приложения x86/x64, затем откат. Сначала без автозапуска.
2. **Довести package manager.** Устойчивость к нехватке диска, ошибкам сохранения журнала, долгоживущим блокировкам DLL и смене времени. Подпись каталога и подписанные релизы потребуют отдельного ключа владельца проекта.
3. **Сделать открытые визуальные ресурсы.** Свои Seven/Vista msstyles, панели, кнопки, иконки, звуки; исходники и воспроизводимая сборка каждого ресурса. Не переносить готовые DLL/темы из пользовательского Revert8Plus.
4. **Расширить интеграцию Open-Shell и OpenGlass.** Реализован типизированный журнал пользовательских настроек с явным allowlist, идемпотентностью и возвратом темы/обоев. Далее — обнаружение версий, проверка совместимости и испытания после входа/перезагрузки. Внешний установщик не маскировать под транзакцию AeroForge.
5. **Alt+Tab.** Проверить собственную реализацию: Alt+Tab, Shift+Tab, Escape, мышь, зависшие окна, UWP, virtual desktops, DPI, elevated windows. Сейчас она скомпилирована, но интерактивные сценарии не пройдены.
6. **Системные модули.** Отдельно испытать Basic/Classic, DWM, UAC. В portable пользовательском host не обещать поддержку secure desktop или winlogon. При необходимости разработать отдельную службу с минимальными полномочиями и безопасным отключением после сбоя.
7. **Экран входа и старые системные страницы.** Собственная реализация/адаптация вместо распространяемых старых Microsoft DLL. Отдельный путь восстановления при ошибке входа.
8. **Дополнительные программы.** Расширить медиатеку, добавить пульт, отдельный backend воспроизведения, игры и интерфейс плагинов гаджетов.
9. **Матрица Windows 11 и ARM64.** Не включать поддержку только по номеру базовой сборки; привязывать к реально проверенным ревизиям и результатам VM-тестов.

## Критерий готового аналога

Все строки FEATURES.md закрыты проверяемой реализацией, лицензии и исходники ресурсов доступны, установка/обновление/удаление испытаны после перезагрузки на заявленных ОС, а восстановление после сбоя возвращает рабочий вход и оболочку. До этого продукт остаётся разработческой сборкой.
