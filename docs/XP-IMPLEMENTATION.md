# XP Luna: реализация и границы проверки

**Контрольная точка по просьбе пользователя; к merge не готово.** Остаётся серьёзный дефект восстановления после отмены. Узкий unload fix дал обычный цикл без новых Explorer ошибок, но cancellation/foreign-edit прогон выявил ещё 3 события. Последний эксперимент `WithDesktopStoppedAsync` удерживает Explorer до конца style transaction; Apply прошёл без событий за 72.02 с, однако Restore остановился на двухсекундном ожидании завершения процесса. Фактический rollback затем проверен отдельно: все XP-журналы RolledBack, исходные native appearance и visual style совпали, RetroBar отсутствует. Гость штатно выключен. Последний эксперимент требует продолжения; результаты промежуточных успешных циклов ниже не являются приёмкой текущего HEAD.

30 октября 2026. Эта ветка заменяет прежние классические рамки XP настоящим совместимым визуальным стилем Luna Blue на Windows 10 LTSC 2021 x64, build 19044. Профиль остаётся экспериментальным. Полная идентичность XP и завершение всех пунктов [задания](tasks/XP.md) не заявляются.

## Механизм

`windows-xp` использует отдельный shell-профиль `windowsxp`. При входе возвращается только собственный ACL-журнал `ClassicSession`; оставшееся чужое ограничение ThemeSection вызывает ошибку. Старые идентификаторы и журналы 95–2000 сохранены.

В существующем `winmim-classic-frames` добавлен режим `basicThemed=1`: он оставляет UxTheme и тематизацию контролов включёнными, отключает DWM non-client rendering для окон через прежний событийный наблюдатель. DWM не завершается. Второй постоянный процесс опроса не добавлен. При выгрузке возвращаются только изменённые наблюдателем окна. `DWMWA_NCRENDERING_POLICY` — атрибут только для записи; проверяется фактический `DWMWA_NCRENDERING_ENABLED`.

Только внутри Explorer режим XP также сообщает отсутствие composition через процессные API hooks и запрашивает basic fallback для CabinetWClass вместо расширенного стеклянного client frame. Последние запрошенные приложением margins сохраняются и возвращаются при выгрузке. Это исправляет отсутствующие границы/кнопки окна и не выключает системную композицию DWM. Основа API: [DwmIsCompositionEnabled](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmiscompositionenabled), [DwmExtendFrameIntoClientArea](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmextendframeintoclientarea). Чужой R2-модуль напрямую не копировался.

XP не включает classic Explorer Lite, classic transparency/UWP/taskbar fixes и конкурирующие модули удаления navigation/command bands. Отключение Ribbon поручено Aerexplorer; в проверенном отдельном folder-процессе всё ещё остаются современные/дублирующиеся полосы. Это открытый дефект, а не законченный XP Explorer. MIT-модуль `fix-basic-caption-text` исправляет цвет текста basic-заголовков, включая системное окно WinMim.

Применение использует существующий адаптер visual style и закреплённый SecureUxTheme 4.0.0. Системные DLL не заменяются. Совместимый стиль остаётся в отдельно проверенном private pack, доступном Themes/DWM; временные файлы журнала не используются как глобально открытый msstyles. Для вызова из CLI обновляется process-local кеш UxTheme через временное скрытое STATIC-окно и синхронный `WM_THEMECHANGED`. Это устраняет ложное чтение прежней темы сразу после успешного переключения и ошибочный rollback.

У операции стиля сохраняются отдельно журналируемые метрики/палитра и `EnableWindowColorization`. XP получает Trebuchet MS в заголовках, Tahoma в контролах и подписях, XP-палитру и метрики. DPI читается в системном контексте; временный thread override ограничен синхронным native-вызовом. `AppliedDPI` не записывается. Новое значение `ChangeKind.XpAppearance` добавлено в конец enum; номера прежних операций и формат native fingerprint сохранены.

При cold boot обнаружена нормализация `LOGFONT.Quality` из 3 в 0. XP теперь сразу записывает `DEFAULT_QUALITY=0`, как Windows сохраняет при входе; сравнение native fingerprint не ослаблено. Это предотвращает ложный конфликт возврата после logon. Для повторного применения сравниваются и фактический журнал, и новый план: новая версия модуля/ресурса не может незаметно использовать старый receipt; игнорируется только генерируемый `SettingsChangeTime` в module INI.

## Личный пакет

В Git находятся только `content/xp/pack-reference.json`, pin SecureUxTheme и инструменты импорта. Закреплены 69 файлов: три стиля семейства Luna, shellstyle, Bliss, 22 ICO, 15 исходных CUR, 22 WAV, две частичные resource-only библиотеки значков с манифестом и отдельный скин меню. Сейчас применяется только Blue. Наличие Metallic/Homestead в перечне не означает готовые варианты Silver/Olive.

Перед остановкой текущего оформления проверяются SHA-256, build, допустимые имена, роли, размеры, ICO/CUR/WAV и отсутствие точки входа у PE-ресурсов. Отсутствующий или изменённый пакет вызывает диагностику до изменения системы. Для XP нет незаметного возврата к значкам 95.

`tools/import_xp_assets.py` извлекает исходные ICO-группы/маски/размеры и CUR-hotspots как данные. `tools/build_xp_icon_libraries.py` переносит 27 групп в частичные shell32/imageres resource-only PE без исполняемого кода. Перенаправляются только запросы значков; отсутствующие группы остаются у текущей Windows. Диалоги, строки и системные DLL из XP не подменяются.

`tools/adapt_xp_menu_skin.py` меняет только текстовую конфигурацию установленного Open-Shell 4.4.198: Tahoma, размеры шрифта и непрозрачность. Исходные bitmap-ресурсы сохранены. Скин размещается отдельно, без записи в Program Files. Закреплённые «Проводник»/«Блокнот» являются настоящими LNK; имя/рисунок пользователя открывают штатное управление учётными записями.

Указатели и 23 события звуков записываются в строго разрешённые значения HKCU и участвуют в общем журнале. Звуки входа/выхода пока являются назначенными событиями; это не подтверждает фактическое воспроизведение при logon/logoff.

Пакет создаётся вне репозитория из отдельно полученных файлов. Сначала подготовьте частичные библиотеки и скин, затем выполните импорт:

```powershell
python tools/build_xp_icon_libraries.py --icons <original-ico-dir> --output <private-resources-dir> --rc <rc.exe> --cvtres <cvtres.exe> --lld <ld.lld.exe>
python tools/adapt_xp_menu_skin.py --source <installed-XP-Luna.skin> --output <private-XP.skin>
python tools/import_xp_assets.py --luna <extracted-Luna-dir> --shell32 <XP-shell32.dll> --user32 <XP-user32.dll> --notepad <XP-notepad.exe> --media <XP-WAV-dir> --resources <private-resources-dir> --menu-skin <private-XP.skin> --output <new-private-pack-dir>
```

Импорт принимает только закреплённые исходные хеши и проверяет все 69 файлов до создания выходного каталога. Для другого законно полученного набора нужен отдельный проверенный манифест. Разместите результат в private lab asset directory, указанном `XpThemePack.PrivateAssets`. Не добавляйте его в Git или публичный архив.

## Применение и возврат

Только в отдельной ВМ со снимком и установленными зависимостями:

```powershell
.\cli\AeroForge.Cli.exe classic-apply --target windows-xp --content .\content --accept-experimental
.\cli\AeroForge.Cli.exe classic-inspect --content .\content
.\cli\AeroForge.Cli.exe classic-restore --content .\content --accept-experimental
```

Блокировки, guard неподдерживаемого компьютера/административного пользователя и журналирование до записи сохранены. Повторное неизменённое применение возвращает прежний receipt. Resume проверяет private pack, стиль и модули; не включает ClassicSession deny и не перезаписывает поздние правки пользователя. При ошибке rollback независимо обрабатывает desktop/shell/panel и сохраняет информацию о конфликтах. Не удаляйте private style, пока он глобально выбран или нужен активному журналу возврата.

Для перехода к Seven сначала выполните `classic-restore`; при активной XP существующая проверка Seven отказывает. XP поверх активной Seven образует обратимый слой поверх её текущего desktop state. Финальную интеграцию владельцев профилей выполняет координатор.

При конфликте восстановление сохраняет изменённое пользователем значение и пишет `RollbackIncomplete`. Изучите запись в «Восстановлении»; не удаляйте журнал и не навязывайте прежнее значение без разбора. Снимок ВМ остаётся аварийным способом возврата.

## Проверено и что остаётся

Сборка: 64 Core, 10 Python, 40 модулей / 58 DLL; контроль SHA-256, архитектуры и ABI прошёл. Неизменённые shell-профили и бинарники прочих модулей сохранены от базы.

В выделенном RU-госте при 100% DPI проверены реальные Luna-рамки/контролы x86/x64 и окно WinMim, включённая тематизация (`flags=3`, themed button), отключённое non-client DWM rendering и белый caption. На окончательном движке прошёл цикл XP → повтор XP → Resume → 95 → XP → Restore с возвратом исходных native appearance/style и без оставшейся RetroBar (56.27 с). Повтор занимал 1.03 с, Resume ещё 0.68 с. Ранее первоначальное применение с ресурсами занимало 9.65–12.56 с, обновление активного профиля с его полным возвратом — 22.80–27.62 с. Материалы конкретного стенда и необработанные журналы хранятся вне Git.

Дополнительный VM-прогон подтвердил отказ отсутствующего CUR до изменений, позднюю отмену после native appearance с полным откатом и сохранение заданного тестом чужого значения Arrow при `RollbackIncomplete`. После явного разрешения созданного тестом конфликта штатный Restore вернул исходное состояние. Пересборка обеих частичных icon DLL и их манифеста дала те же SHA-256; все 25 bitmap resources скина меню остались побайтно прежними.

После исправления Quality=0 пройдены штатное выключение/холодный запуск, вход обычного пользователя и автоматический Resume. Повтор сохранил прежний receipt (1.25 с), следующий Resume занял ещё 0.74 с; полный цикл XP → 95 → XP → исходное состояние после загрузки завершился за 49.54 с. Native appearance и visual style сверены с резервной копией до XP, активного classic-профиля и RetroBar после Restore нет. Этот прогон выполнен на подготовленной исходной системе стенда, не на заново установленной чистой Windows.

**Поздняя проверка событий выявила ограничение этих ранних прогонов:** совпадение состояния после rollback не означало отсутствие падений Explorer. За 30 минут старого порядка переключений зарегистрированы 9 событий Application Error: в том числе `aero-tray.dll_unloaded` и адрес, впоследствии занятый caption-модулем. RVA `0x2FA0` совпал с `WindhawkUtils::SubclassProcWrapper` старого Aero Tray; upstream Uninit вызывает `DestroyWindow` из чужого потока и не снимает subclass явно. Часть событий в ntdll отдельно не атрибутирована.

Добавлен ограниченный стендом `ShellHost.StopDesktopAsync`: перед выгрузкой DLL завершаются только Explorer-процессы текущего сеанса с проверенным системным путём, короткий переход удерживает автостарт оболочки от гонки, затем Explorer возобновляется с остановленным host. Все Classic/XP Apply, rollback и Restore используют этот порядок. Изменения внешнего вида других профилей и их бинарников не требуются; обычный `StopAsync` сохранён для остальных клиентов. Постоянного нового watcher-процесса нет. Приёмочный runner теперь дополнительно отказывает при любом новом Explorer Application Error (Id 1000), даже если журналы и native state успешно восстановлены. Прямые Seven-сценарии, использующие прежний StopAsync, требуют отдельной интеграции координатора.

С этим исправлением первоначальный вход в XP завершился за 17.47 с (включая 2 с контроля событий), `explorerErrors=0`. Повторный полный цикл XP → повтор → Resume → 95 → XP → Restore завершился за 67.14 с: прежний receipt сохранён, native/style исходного состояния совпали, новых Explorer Application Error — 0. Повтор — 1.14 с, Resume ещё 0.65 с. Более ранние времена выше относятся к порядку остановки до этого исправления и не являются доказательством отсутствия сбоев.

В 10.10-секундном стабильном интервале на двух vCPU: Windhawk 0 мс CPU / 12.44 MiB working set; два Explorer вместе 0 мс / 159.27 MiB; RetroBar 187.5 мс / 125.49 MiB (около 0.93% двух vCPU). Это короткая выборка, не длительный нагрузочный тест. Все 23 назначенных звуковых пути существовали. Наблюдатель окон событийный; постоянного повторного сканирования в нём нет.

Не завершены: собственные XP address/Go/throbber/Common Tasks/search и согласование всех property/dialog/tray поверхностей; Silver/Olive; сравнение с установленной оригинальной XP при одинаковых параметрах; en-US; UAC/logon appearance и реальное воспроизведение звуков входа. Полной библиотеки XP-значков для каждой современной панели также нет: частичные ресурсы намеренно имеют fallback.

125% DPI проверены пока только в расчёте плана/метрик, не визуальным VM-прогоном; закреплённая Luna имеет ограничение исходных ресурсов 96 DPI. Не засчитаны реальные Start-click/Ctrl+Esc, menu actions, tray/volume и maximized Explorer: канал управления консолью не обеспечил надёжного ввода, затем Computer Use был остановлен физической Escape. Запуск Open-Shell `-open` ради снимка не является проверкой Start-кнопки. Успешный `Loaded` не доказывает визуальное сходство или работоспособность команды.
